# Annotation API Cleanup & Naming Conventions

**Date:** 2026-02-19  
**Status:** Proposed  
**Author:** Klas Kalaß & AI Analysis (copilot/claude)  
**Related:** [021-vocab-generating.md](021-vocab-generating.md)

## Goals

1. **Simplest possible annotation API** - User-facing names are clean, intuitive, no unnecessary prefixes
2. **Clear package boundaries** - Each layer has distinct naming conventions to avoid confusion
3. **Consistent naming** - Eliminate current inconsistencies (some use `Lcrd*`, some don't)
4. **Type-safety** - Clear distinction between annotations and parameter classes

## Package Hierarchy & Naming Conventions

### Layer 1: `locorda_annotations` (User-Facing API)

**Purpose:** Annotations developers write in their application code.

**Naming Rule:** **Cleanest, shortest names** - no prefixes or suffixes.

**Structure:**
```
packages/locorda_annotations/lib/
  src/
    annotations/
      root_resource.dart       # @RootResource
      sub_resource.dart        # @SubResource
      local_resource.dart      # @LocalResource
      index_item.dart          # @IndexItem
      group_key.dart           # @GroupKey
    
    parameters/
      full_index.dart          # FullIndex (parameter class)
      group_index.dart         # GroupIndex (parameter class)
      merge_contract.dart      # MergeContract (parameter class)
      merge_contracts.dart     # MergeContracts (standard imports)
      grouping_property.dart   # GroupingProperty
      regex_transform.dart     # RegexTransform
    
    vocabulary/
      app_vocab.dart           # Re-export from rdf_mapper
  
  annotations.dart             # Public export
```

**Classes:**

| Current Name | New Name | Type | Location |
|-------------|----------|------|----------|
| `LcrdRootResource` | `RootResource` | Annotation | `annotations/` |
| `LcrdSubResource` | `SubResource` | Annotation | `annotations/` |
| `RdfLocalResource` (direct use) | `LocalResource` | Annotation | `annotations/` |
| `LcrdIndexItem` | `IndexItem` | Annotation | `annotations/` |
| `LcrdGroupKey` | `GroupKey` | Annotation | `annotations/` |
| `LcrdFullIndex` | `FullIndex` | Parameter | `parameters/` |
| `LcrdCrdt` | `MergeContract` | Parameter | `parameters/` |
| `LcrdMappings` | `MergeContracts` | Constants | `parameters/` |
| `LcrdGroupingProperty` | `GroupingProperty` | Parameter | `parameters/` |
| `LcrdRegexTransform` | `RegexTransform` | Parameter | `parameters/` |

### Layer 2: `locorda_objects` (Generated Config)

**Purpose:** Configuration objects created by code generator, consumed by app during initialization.

**Naming Rule:** `*Config` suffix to distinguish from annotations and runtime data.

**Classes:**

| Current Name | New Name | Purpose |
|-------------|----------|---------|
| `FullIndex` | `FullIndexConfig` | Generated full index configuration |
| `GroupIndex` | `GroupIndexConfig` | Generated group index configuration |
| `IndexItem` | `IndexItemConfig` | Generated index item configuration |
| `ResourceConfig` | `ResourceConfig` | (unchanged) |
| `LocordaConfig` | `LocordaConfig` | (unchanged) |

**Example:**
```dart
// Generated by builder
final config = LocordaConfig(
  resources: [
    ResourceConfig(
      type: Note,
      crdtMapping: Uri.parse('https://myapp.com/contracts/note-v1#'),
      indices: [
        FullIndexConfig(
          localName: 'default',
          itemFetchPolicy: ItemFetchPolicy.prefetch,
        ),
      ],
    ),
  ],
);
```

### Layer 3: `locorda_core` (Runtime Data)

**Purpose:** Runtime representation of configuration and state.

**Naming Rule:** `*Data` suffix to distinguish from config objects.

**Classes:**

| Current Name | Status | Purpose |
|-------------|--------|---------|
| `FullIndexData` | (unchanged) | Runtime full index state |
| `GroupIndexData` | (unchanged) | Runtime group index state |
| `IndexItemData` | (unchanged) | Runtime index item state |
| `ResourceConfigData` | (unchanged) | Runtime resource configuration |
| `SyncEngineConfig` | (unchanged) | Runtime sync engine config |

**Base Classes:**
- `ConfigBase` - Base for all config classes (unchanged)
- `CrdtIndexConfigBase` - Base for index configs (unchanged)
- `IndexItemConfigBase` - Base for index item configs (unchanged)

## User-Facing API Examples

### Before (Current)

```dart
import 'package:locorda_annotations/locorda_annotations.dart';

const appVocab = AppVocab(appBaseUri: appBaseUrl);

@LcrdRootResource(
  PersonalNotesVocab.PersonalNote,
  LcrdCrdt('$appBaseUrl/mappings/personal-note-v1#'),
  fullIndex: LcrdFullIndex(),
)
class Note {
  @RdfProperty(PersonalNotesVocab.title)
  final String title;
}

@LcrdGroupKey(
  Note,
  localName: 'byMonth',
  groupingProperties: [
    LcrdGroupingProperty(
      Dc.created,
      transforms: [LcrdRegexTransform(r'(\d{4}-\d{2})-.*', r'$1')],
    ),
  ],
)
class NotesByMonth { }
```

### After (Proposed)

```dart
import 'package:locorda_annotations/annotations.dart';

const appVocab = AppVocab(appBaseUri: appBaseUrl);

@RootResource(appVocab)  // Clean, simple!
class Note {
  final String title;  // Auto-matched to dc:title
}

@GroupKey(
  Note,
  localName: 'byMonth',
  groupingProperties: [
    GroupingProperty(
      Dc.created,
      transforms: [RegexTransform(r'(\d{4}-\d{2})-.*', r'$1')],
    ),
  ],
)
class NotesByMonth { }
```

### All 4 RootResource Variants

```dart
// 1. Default: Both vocabulary + merge contract generated
@RootResource(appVocab)
class Note { }

// 2. External vocab (Schema.org) + generated contract
@RootResource.externalVocab(
  Schema.Article,
  appBaseUrl,
)
class BlogPost { }

// 3. Generated vocab + external contract
@RootResource.externalContract(
  appVocab,
  'https://crdt-contracts.org/note-v1#',
)
class StandardNote { }

// 4. Both external
@RootResource.external(
  Schema.Recipe,
  'https://schema.org/contracts/recipe-v1#',
)
class Recipe { }
```

### Custom Index Configuration

```dart
@RootResource(
  appVocab,
  fullIndex: FullIndex(itemFetchPolicy: ItemFetchPolicy.onRequest),
  mergeContractVersion: 'v2',
)
class Note { }
```

## Implementation Strategy

### Phase 1: `locorda_annotations` Package Restructure

1. **Create new directory structure:**
   - `src/annotations/`
   - `src/parameters/`
   - `src/vocabulary/`

2. **Create new annotation classes:**
   ```dart
   // src/annotations/root_resource.dart
   class RootResource extends RdfGlobalResource {
     final AppVocab? _vocab;
     final IriTerm? _explicitClassIri;
     // ... (full implementation from 021-vocab-generating.md)
   }
   ```

3. **Create new parameter classes:**
   ```dart
   // src/parameters/full_index.dart
   class FullIndex {
     final String localName;
     final ItemFetchPolicy itemFetchPolicy;
     const FullIndex({
       this.localName = 'default',
       this.itemFetchPolicy = ItemFetchPolicy.prefetch,
     });
   }
   ```

4. **Update exports:**
   ```dart
   // lib/annotations.dart
   export 'src/annotations/root_resource.dart';
   export 'src/annotations/sub_resource.dart';
   export 'src/annotations/local_resource.dart';
   export 'src/annotations/index_item.dart';
   export 'src/annotations/group_key.dart';
   
   export 'src/parameters/full_index.dart';
   export 'src/parameters/group_index.dart';
   export 'src/parameters/merge_contract.dart';
   export 'src/parameters/merge_contracts.dart';
   export 'src/parameters/grouping_property.dart';
   export 'src/parameters/regex_transform.dart';
   
   export 'package:locorda_rdf_mapper_annotations/annotations.dart'
       show AppVocab;
   ```

### Phase 2: `locorda_objects` Package Renames

Rename generated config classes to add `Config` suffix:

```dart
// lib/src/config/locorda_config.dart
class IndexItemConfig extends IndexItemConfigBase { ... }  // was: IndexItem
class FullIndexConfig extends FullIndexConfigBase { ... }  // was: FullIndex
class GroupIndexConfig extends GroupIndexConfigBase { ... } // was: GroupIndex
```

### Phase 3: Builder Updates

1. **Update annotation scanning:**
   ```dart
   // Recognize new annotation names
   if (annotation is RootResource) { ... }
   if (annotation is SubResource) { ... }
   ```

2. **Generate with Config suffix:**
   ```dart
   // Generate FullIndexConfig instead of FullIndex
   'FullIndexConfig(localName: \'${index.localName}\', ...)'
   ```

3. **Add deprecation warnings:**
   ```dart
   // Warn if old annotations are used
   if (annotation.runtimeType.toString().startsWith('Lcrd')) {
     log.warning(
       'Deprecated annotation @${annotation.runtimeType} used. '
       'Use @${annotation.runtimeType.toString().replaceFirst('Lcrd', '')} instead.',
     );
   }
   ```

### Phase 4: Documentation Updates

1. Update getting-started guide with new annotation names
2. Update example apps (personal_notes_app)
3. Update API documentation with clearer explanations
4. Add migration guide for existing code

## Rationale: Why Remove `Lcrd` Prefix?

### Current Issues

1. **Inconsistency:** Some classes have `Lcrd` prefix, some don't (e.g., `AppVocab`, `ItemFetchPolicy`)
2. **Verbosity:** Writing `@LcrdRootResource` repeatedly gets tedious
3. **Unclear purpose:** "Lcrd" doesn't communicate meaning to new users
4. **Generic enough:** In `locorda_annotations` package, context is clear without prefix

### Comparison with Other Frameworks

| Framework | Annotation Style | Example |
|-----------|-----------------|---------|
| Flutter | No prefix | `@immutable`, `@protected` |
| Spring Boot | No prefix | `@RestController`, `@Service` |
| Angular | No prefix | `@Component`, `@Injectable` |
| **Locorda (current)** | `Lcrd` prefix | `@LcrdRootResource` |
| **Locorda (proposed)** | No prefix | `@RootResource` |

### Benefits of Removal

1. **Cleaner code:** `@RootResource(appVocab)` vs `@LcrdRootResource(appVocab)`
2. **Easier to type:** Developers write this frequently
3. **More intuitive:** Name clearly describes purpose
4. **Consistent with ecosystem:** Follows Dart/Flutter conventions

## Builder Warnings for Direct RDF Usage

Add helpful warnings when developers use RDF mapper annotations directly:

```dart
// In annotation scanner
if (annotation is RdfGlobalResource && 
    annotation.runtimeType.toString() == 'RdfGlobalResource') {
  log.warning(
    'Direct use of @RdfGlobalResource detected at ${element.name}. '
    'For CRDT sync support, use @RootResource or @SubResource instead. '
    'See: https://docs.locorda.dev/annotations',
  );
}
```

**When to warn:**
- Direct use of `@RdfGlobalResource` → suggest `@RootResource`
- Direct use of `@RdfLocalResource` → suggest `@LocalResource`

**When NOT to warn:**
- Custom annotation extending `RdfGlobalResource` (advanced use case, legitimate)

## Migration Path for Existing Code

### Automatic Migration (via Codemod)

Provide a migration script:

```dart
// tool/migrate_annotations.dart
void main() {
  // Find all .dart files
  // Replace:
  //   @LcrdRootResource → @RootResource
  //   @LcrdSubResource → @SubResource
  //   LcrdFullIndex → FullIndex
  //   LcrdCrdt → MergeContract
  //   etc.
}
```

### Manual Migration Steps

1. **Update imports:**
   ```dart
   // Before
   import 'package:locorda_annotations/locorda_annotations.dart';
   
   // After (same)
   import 'package:locorda_annotations/annotations.dart';
   ```

2. **Update annotations (find/replace):**
   - `@LcrdRootResource` → `@RootResource`
   - `@LcrdSubResource` → `@SubResource`
   - `@LcrdGroupKey` → `@GroupKey`
   - etc.

3. **Update parameter classes:**
   - `LcrdFullIndex` → `FullIndex`
   - `LcrdCrdt` → `MergeContract`
   - `LcrdMappings.coreV1` → `MergeContracts.coreV1`

4. **Run build_runner:**
   ```bash
   dart run build_runner build --delete-conflicting-outputs
   ```

## Summary

This proposal achieves:

✅ **Cleaner API** - Remove `Lcrd` prefix, use intuitive names  
✅ **Consistency** - All locorda annotations follow same pattern  
✅ **Clear boundaries** - Distinct naming in each package layer  
✅ **Type safety** - Separate directories for annotations vs parameters  
✅ **Documentation clarity** - Easier to explain to new users

**Recommendation:** Implement this cleanup before 1.0 release while breaking changes are acceptable.
